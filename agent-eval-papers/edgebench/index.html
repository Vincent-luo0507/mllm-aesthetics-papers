1Introduction

Scaling laws for pretraining [31, 35] revealed that model capability improves predictably with data and compute, an insight that guided much of the progress in the years that followed [2, 3, 22, 24, 25, 46, 50–52, 54, 55]. Now, as large language models enter the agent era, they are being deployed into a growing range of real world environments where they can try to learn from interaction, yet whether learning from such environments obeys a clean scaling law remains unknown. Analyzing roughly 38,000 hours of agent environment interaction across 134 diverse real world tasks, we find, to the best of our knowledge, the first evidence that when agents learn from real world environments, overall performance follows a log-sigmoid scaling law as a function of environment interaction time, achieving remarkably high precision with R2 = 0.998.
预训练缩放定律 [31, 35] 表明，模型能力随数据与算力的增长而可预测地提升；这一洞察为此后多年的进展提供了指引 [2, 3, 22, 24, 25, 46, 50–52, 54, 55]。如今，随着大语言模型迈入智能体时代，它们正被部署到日益多样的真实世界环境中，有机会通过交互进行学习；然而，此类环境中的学习是否服从一条清晰的缩放定律，此前仍无答案。我们分析了约 38,000 小时的智能体-环境交互数据，覆盖 134 项多样化的真实世界任务；据我们所知，这是首个证明如下结论的证据：智能体从真实世界环境中学习时，整体性能作为环境交互时长的函数遵循 log-sigmoid 缩放定律，且拟合精度极高（R2 = 0.998）。

Even when raw data exists, it omits the human process behind it: the trial-and-error, the interpretation of evidence, and the adaptation to feedback through which experts actually reach results. The real world also never stands still: human knowledge keeps advancing, and new tools, discoveries, and problems continually emerge that no fixed training corpus can anticipate. Therefore, an agent’s ability to learn from its environment and improve task performance is central to deploying AI systems at scale in the real world.

2.1Design Goals

EdgeBench aims to measure whether an autonomous agent can learn from experience in an unfamiliar real world environment. This requires two properties from a benchmark that existing evaluations lack:
EdgeBench 旨在衡量自主智能体能否在陌生的真实世界环境中从经验中学习。这要求基准具备两项现有评测所缺乏的性质：
• Ultra-long-horizon, diverse tasks. Learning behaviors such as exploration, strategy revision, and experience accumulation need time and complexity to emerge. Short tasks are usually solved from memory rather than learning, so measuring learning calls for long-horizon tasks. Because learning is a general capability, these tasks must also span diverse domains.
• 超长时程且多样的任务。探索、策略修正、经验积累等学习行为需要足够的时间与复杂度才会显现；短任务通常靠记忆而非学习来完成。因此，衡量学习必须使用长时程任务；同时，由于学习是一种通用能力，任务还须覆盖多样的领域。
• Realistic, multi-level feedback. In practice, human experts learn from rich feedback: test failures, experimental results, unexpected phenomena, authoritative judgments, and more. A benchmark that cannot offer such rich feedback cannot measure learning, and leaves the agent guessing what the evaluation actually rewards. We need feedback that approximates the real world, so we can measure true, general-purpose learning.
• 贴近现实的多层次反馈。人类专家在实践中依靠丰富的反馈学习：测试失败、实验结果、意外现象、权威判定，等等。无法提供这种丰富反馈的基准既无法衡量学习，也让智能体只能猜测评测真正奖励什么。反馈必须逼近真实世界，我们才能度量真实的、通用的学习能力。
The first requirement motivates our task taxonomy (§2.2): 134 tasks across six capability families, each designed as a day-scale challenge that supports frontier models running for at least 12 hours. The second motivates our evaluation protocol (§2.3): each task individually simulates its own slice of the real world, providing isolated work and judge environments, local agent-driven feedback, submission-gated judge feedback, and host-side trajectory measurement.
第一条要求促成了我们的任务分类体系（§2.2）：134 项任务横跨六个能力族，每项任务都设计为天尺度的挑战，支持前沿模型连续运行至少 12 小时。第二条要求则促成了我们的评测协议（§2.3）：每项任务各自模拟真实世界的一个切片，提供相互隔离的工作环境与评审环境、智能体驱动的本地反馈、以提交为闸门的评审反馈，以及主机侧的轨迹测量。

2.2Task Taxonomy

We searched for real world tasks that satisfy two criteria: a performance ceiling high enough that no current
我们按两条标准搜寻真实世界任务：性能上限足够高，任何现有
agent can saturate it, and a workflow that supports continuous learning rather than one-shot completion. This search, conducted in collaboration with domain experts across fields, identified six capability families and yielded 134 curated tasks (Figure 2):
智能体都无法将其饱和；工作流须支持持续学习而非一次性完成。通过与各领域专家合作开展遴选，我们确定了六个能力族，并整理出 134 项任务（图 2）：
• Scientific Problems & ML (39 tasks). Each task uses real world research data and experimental settings sourced from working scientists. Domain expertise is essential: agents must formulate hypotheses, choose models, validate against noisy observations, and refine iteratively. Many problems are open-ended, with no known optimal solution.
• 科学问题与 ML（39 项任务）。每项任务使用一线科研人员提供的真实研究数据与实验设置。领域专业知识不可或缺：智能体必须提出假设、选择模型、对照含噪观测进行验证，并迭代改进。许多问题没有已知最优解，本质上是开放式的。
• Systems & Software Engineering (36 tasks). Agents work on production-grade codebases where a single task may require thousands of lines of change, with over 100,000 lines in the largest cases. Because the code spans interdependent modules, an agent must reason about cross-module coupling while meeting both correctness and performance targets.
• 系统与软件工程（36 项任务）。智能体在生产级代码库上工作，单个任务可能涉及数千行改动，最大的案例超过 100,000 行。代码横跨相互依赖的多个模块，智能体既要推理跨模块耦合，又要同时满足正确性与性能目标。
• Combinatorial Optimization (19 tasks). These are open-ended, predominantly NP-hard problems where exact methods are intractable and progress depends on designing, tuning, and iterating on heuristic search strategies. Even strong solvers have room to improve with additional time and feedback.
• 组合优化（19 项任务）。这些问题多为开放式，且以 NP-hard 问题为主：精确方法难以处理，进展依赖于启发式搜索策略的设计、调优与迭代。即便是强大的求解器，也有借助更多时间与反馈继续改进的空间。
• Professional Knowledge Work (19 tasks). These tasks reproduce real white-collar deliverables across finance, education, healthcare, and legal domains, matching work that would take a human professional with three or more years of experience roughly three full days to complete. Many tasks feature carefully designed rubrics and multi-round delivery feedback that approximate real client review cycles, so agents can learn from structured critique and revise iteratively.
• 专业知识工作（19 项任务）。这些任务复现金融、教育、医疗与法律领域的真实白领交付物，其工作量相当于一名拥有三年以上经验的人类专业者投入约三个完整工作日。许多任务配有精心设计的评分细则与多轮交付反馈，贴近真实的客户评审周期，智能体由此可以从结构化的批评意见中学习并迭代修改。
• Formal Math & Theorem Proving (13 tasks). These tasks sit at the frontier of mathematical difficulty and require building large-scale machine-checked proofs in Lean, coupling deep mathematical insight with substantial formal-verification engineering. Most are newly created for EdgeBench and designed to support iterative progress: agents receive structured intermediate guidance and can extend partial proofs incrementally.
• 形式数学与定理证明（13 项任务）。这些任务处于数学难度的前沿，要求在 Lean 中构建大规模机器可验证的证明，将深刻的数学洞察与可观的形式验证工程相结合。其中大多数是为 EdgeBench 新建的，且被设计为支持迭代推进：智能体可获得结构化的中间提示，并逐步扩展未完成的证明。
• Interactive Games & Simulators (8 tasks). These are real games designed for human players, where proficient humans typically invest tens of hours to master the mechanics. The state spaces are enormous and each run is procedurally distinct, so agents face strong out-of-distribution pressure. Agents must develop and refine strategies through high-frequency interaction across many episodes.
• 交互游戏与模拟器（8 项任务）。这些均为面向人类玩家的真实游戏，熟练玩家通常需要数十小时才能掌握其机制。状态空间巨大，且每次运行都由程序生成、彼此不同，智能体因此面临强烈的分布外压力，必须通过大量轮次的高频交互来开发并打磨策略。
Tasks whose primary difficulty lies in visual understanding, especially GUI operation, are excluded. When success depends on the vision backbone rather than iterative reasoning, learning ability and perceptual capability are hard to separate.
我们排除了主要难度集中在视觉理解（尤其是 GUI 操作）的任务：当成功取决于视觉骨干网络而非迭代推理时，学习能力与感知能力便难以解耦。

2.3Feedback Loop and Evaluation Protocol

Real world engineering and research workflows rarely provide a single final answer check. Instead, practitioners iterate through two complementary feedback loops: a fast local loop for exploration, debugging, and refinement, and a slower external loop that provides authoritative calibration through deployment, peer review, benchmark evaluation, or stakeholder feedback. The local loop enables rapid progress, while the external loop guards against overfitting to visible checks and exposes failures that are not captured by the developer’s own tests.
真实世界的工程与研究工作流很少只提供一次最终答案核对。实际做法是在两个互补的反馈回路中迭代：一个是用于探索、调试与改进的快速本地回路；另一个是较慢的外部回路，通过部署、同行评审、基准评测或利益相关者反馈提供权威校准。本地回路保障快速推进，外部回路则防止对可见检查的过拟合，并暴露开发者自身测试未能覆盖的失败。
EdgeBench adopts this dual-loop structure to measure learning rather than endpoint success (Figure 3). The inner loop is local and agent-driven: agents can inspect a writable workspace, run tests or simulators, observe errors, and revise their artifacts. The outer loop is judge-mediated: submitted artifacts are evaluated against hidden cases or private grading criteria, returning calibrated scores, verdicts, or diagnostics. Across task families, this pattern is instantiated through different mechanisms: tests and profilers for software tasks, development splits and validators for scientific tasks, local testers and hidden seeds for optimization tasks, proof-checker states for theorem proving, episode scores for games, and rubrics for professional knowledge work.
EdgeBench 采用这种双回路结构来度量学习而非终点成败（图 3）。内回路在本地、由智能体驱动：智能体可以查看可写工作区、运行测试或模拟器、观察报错并修改自己的产物。外回路则由评审者居中协调：提交的产物会对照隐藏用例或私有评分标准进行评估，返回校准过的分数、判定或诊断信息。这一模式在不同任务族中以不同机制实现：软件任务用测试与性能剖析器，科学任务用开发集与验证器，优化任务用本地测试器与隐藏种子，定理证明用证明检查器状态，游戏用轮次得分，专业知识工作用评分细则。
The protocol is implemented with an isolated work–judge evaluation harness. During a run, the agent works inside a work container holding the task materials and local validation tools, but no hidden evaluation assets. The agent can actively submit its current artifacts to a separate judge container, which runs the hidden evaluation and returns the feedback specified by the task. A host-side judge server mediates this outer loop, including submission queues, cooldowns, authentication, and support for asynchronous grading on long-running evaluations, allowing agents to continue working while submitted jobs are being judged. Appendix C gives examples of task-design failure modes that motivated this isolation and submission-mediated design.
该协议由一个工作与评审相互隔离的评测 harness 实现。运行期间，智能体在一个工作容器内工作，容器中装有任务材料与本地验证工具，但不含任何隐藏评测资产。智能体可将当前产物主动提交至独立的评审容器，由后者运行隐藏评测并返回任务规定的反馈。这一外回路由主机侧的评审服务器居中协调，涵盖提交队列、冷却时间、认证，以及对长时间评测的异步评分支持，使智能体在提交的作业等待评审期间可以继续工作。附录 C 给出了若干任务设计失败模式的示例，正是它们促成了这种隔离与提交居中的设计。
For trajectory measurement, the evaluation harness also performs host-side auto-evaluation at fixed intervals. These snapshots are scored through the hidden judge and recorded for analysis, but the results are not shown to the agent. This lets EdgeBench measure improvement even between explicit submissions, while preserving the distinction between agent-visible feedback and evaluator-only measurement.

3Scaling Laws of Learning from Real World Environments

Pretraining scaling laws classically model language-model loss as a power-law function of training scale, including the amount of pretraining data [31, 35]. By contrast, benchmark performance is a task-level readout of model capability, shaped by the difficulty thresholds induced by tasks, examples, and scoring criteria. Prior work has found that it is well described under pretraining scale-up by a log-sigmoid curve [7, 22, 56, 61].
经典的预训练缩放定律将语言模型损失建模为训练规模（包括预训练数据量）的幂律函数 [31, 35]。相比之下，基准性能是模型能力在任务层面的读数，其形态由任务、样例与评分标准所设定的难度阈值决定。已有工作发现，在预训练规模扩大过程中，基准性能可以很好地用一条 log-sigmoid 曲线描述 [7, 22, 56, 61]。
Beyond learning from human-collected training data, modern agents such as GPT-5.5 and Claude Opus 4.8 can continue to learn from their environments after deployment. On a task, they can acquire new information through interaction and improve their performance over time. Yet it remains unclear whether this form of learning obeys any similarly simple scaling law. EdgeBench provides 134 diverse real world tasks with executable environments, informative feedback, and at least 12-hour interaction windows, allowing us to study how agents improve through interaction with their environments. Analyzing five frontier agents over roughly 38,000 hours of environment interaction across 134 diverse real world tasks, we find that a log-sigmoid curve fits environment learning performance precisely. Thus, learning from the environment and learning from pretraining data induce the same mathematical scaling form.
除了从人类收集的训练数据中学习之外，GPT-5.5、Claude Opus 4.8 等现代智能体在部署后还能继续向环境学习：在任务执行过程中，它们通过交互获取新信息，并随时间推移提升性能。然而，这种学习是否同样服从某条简单的缩放定律，此前并不清楚。EdgeBench 提供 134 项带可执行环境的多样真实世界任务，配有有信息量的反馈与至少 12 小时的交互窗口，使我们得以研究智能体如何通过与环境的交互而改进。我们对五个前沿智能体在 134 项多样真实世界任务上约 38,000 小时的环境交互进行了分析，发现 log-sigmoid 曲线能精确拟合环境学习性能。由此可见，向环境学习与向预训练数据学习服从同一数学缩放形式。

4Agent Learning Speed Doubles Approximately Every Three Months

Frontier agents can now improve through interaction with task environments. This raises a separate question: are newer models learning from their environments faster? We measure this by comparing how much performance each agent gains over a fixed interaction budget across model release dates.
如今的前沿智能体能通过与任务环境的交互不断改进。由此引出一个独立的问题：更新的模型是否向环境学得更快？我们的度量方式是：在固定的交互预算下，比较各智能体获得的性能增益，并按模型发布日期排列。

4.1Experimental Design

Disentangling prior knowledge from environment learning. A high score may reflect what the model already knew rather than what it learned during the run. 5.2Agents Do Learn from Experience beyond Repeated Sampling

Motivation. A rising best-so-far curve does not by itself prove that an agent is learning. Running longer also gives more chances to stumble on a good solution: with enough independent tries, the best of them climbs by luck alone. We therefore test whether the agent’s accumulated experience adds value beyond such repeated sampling under the same total time budget.
研究动机。迄今最优曲线持续上升，本身并不能证明智能体在学习：运行更久意味着有更多机会碰上好解——只要独立尝试足够多，其中最好的结果单凭运气也会水涨船高。因此我们检验：在相同总时间预算下，智能体积累的经验能否在重复采样之外带来额外价值。
Setup. We give Opus 4.8 the same 12-hour budget on each of 17 tasks and compare two ways of spending it, with versus without accumulated experience. 6Related Work

Existing benchmarks cover major parts of agent capability but rarely measure how an agent improves within a run. Closed-form QA, math, and coding benchmarks such as MMLU [28], AIME [43], and HumanEval [11], together with endpoint patch benchmarks such as SWE-bench [34], evaluate final answers or final patches. More agentic and work-oriented benchmarks, including GDPval [57], Agents’ Last Exam [66], and FrontierCode [39], broaden the task interface to professional deliverables, computer-use workflows, or production code changes. Their central reported quantities, however, remain end-state measures: task success, artifact quality, pass rate, or readiness for production. EdgeBench instead measures the improvement trajectory over time.
现有基准覆盖了智能体能力的主要方面，却很少度量智能体在单次运行内如何改进。封闭式问答、数学与编程基准如 MMLU [28]、AIME [43]、HumanEval [11]，以及端点补丁基准 SWE-bench [34]，评估的都是最终答案或最终补丁。更具智能体属性、更贴近实际工作的基准——如 GDPval [57]、Agents' Last Exam [66] 与 FrontierCode [39]——将任务接口拓展到专业交付物、计算机操作工作流或生产代码变更；但其核心报告指标仍是终态度量：任务成功率、产物质量、通过率或生产就绪度。EdgeBench 则度量随时间演化的改进轨迹。
Some benchmarks study learning, but they focus on restricted domains and shorter horizons. CL-bench [21], EvaLearn [19], and Continual Learning Bench [4] evaluate whether models improve from a static context or static information streams whose content is not primarily shaped by the agent’s actions within a single task. Iterative optimization benchmarks such as MLE-bench [10], MLS-Bench [40], Frontier-Eng [14], Frontier- CS [41], and ALE-Bench [33] further include repeated attempts, empirical feedback, or visible metrics. The closest long-horizon agentic comparators are AutoLab [76] and FrontierSWE [15]: both evaluate agents that repeatedly edit executable artifacts and incorporate feedback. EdgeBench differs by covering a broader range of executable domains, using a day-scale task contract, and applying the same trajectory metrics consistently across all tasks.
另有一些基准研究学习，但局限于较窄的领域与较短的时程。CL-bench [21]、EvaLearn [19] 与 Continual Learning Bench [4] 评估模型能否从静态上下文或静态信息流中改进，而这些信息流的内容并不主要由智能体在单个任务内的行动所塑造。迭代优化类基准——如 MLE-bench [10]、MLS-Bench [40]、Frontier-Eng [14]、Frontier- CS [41] 与 ALE-Bench [33]——进一步引入重复尝试、经验反馈或可见指标。与本文最接近的长时程智能体工作是 AutoLab [76] 与 FrontierSWE [15]：两者都评测反复编辑可执行产物并纳入反馈的智能体。EdgeBench 的差异在于：可执行领域覆盖更广、采用天尺度任务契约，并在所有任务上统一应用同一套轨迹指标。
Scaling laws have been widely studied in prior work, but learning from diverse real-world environments remains underexplored. Classical scaling laws study pretraining, relating loss or benchmark performance to model size, data, and compute [31, 35]; later work studies bounded benchmark performance curves as model scale increases [7, 56, 61, 80]. Test-time scaling laws have also been studied across several inference-time methods: plain repeated sampling [9, 11, 38], search, revision, or verifier-guided compute allocation [64, 74], and long-chain-of-thought inference in reasoning models [16, 47]. Agentic test-time scaling has been observed in computer-use and browsing agents [49, 68], studied through interaction-length scaling [62], and revisited through long-horizon human-agent comparisons [42]. These studies are closer to our setting but cover narrower domains or fewer tasks and do not establish a cross-domain scaling law. Reinforcement-learning scaling is also relevant because it studies learning from environment feedback [30, 36], while EdgeBench measures elapsed interaction time in deployed agent trajectories. This paper introduced EdgeBench, a benchmark for studying how agents learn from real-world environments over day-long horizons. Across 134 diverse executable tasks and roughly 38,000 hours of environment interaction, we find that aggregate learning trajectories follow a precise log-sigmoid relationship with interaction time. The same form appears across task families, remains stable over longer horizons, and supports forecasting later performance from early trajectories. We also find that agent learning speed has improved rapidly across recent frontier model generations.
本文提出了 EdgeBench，一个用于研究智能体如何在天级时程中从真实世界环境学习的基准。在 134 项多样的可执行任务与约 38,000 小时的环境交互上，我们发现聚合学习轨迹与交互时间之间服从精确的 log-sigmoid 关系；同一形式在各任务族中普遍出现，在更长时程下保持稳定，并能支持由早期轨迹预测后期性能。我们还发现，智能体学习速度在近期前沿模型代际间快速提升。
These results suggest that learning from environments is not merely a collection of idiosyncratic task outcomes, but a measurable scaling object. Unlike many aggregate capability curves, environment-learning trajectories expose the intermediate attempts, feedback, and revisions through which progress occurs. This makes EdgeBench useful not only for ranking agents, but for studying how agents acquire and reuse experience. More broadly, the regularity we observe suggests that post-deployment learning from rich environments may deserve the same systematic scaling attention that pretraining has received.
这些结果表明，向环境学习并非一连串彼此特异的任务结局，而是一个可度量的缩放对象。与许多聚合能力曲线不同，环境学习轨迹完整记录了进展发生所经的中间尝试、反馈与修改。因此，EdgeBench 不仅可用于对智能体排名，也可用于研究智能体如何获取与复用经验。更宏观地看，我们观察到的规律性提示：部署后从丰富环境中的学习，或许值得获得与预训练同等的系统性缩放研究。

A Evaluation HarnessA 评测 Harness

A standard unit-test harness is not enough for day-long runs. The benchmark must hide evaluation assets, support repeated submissions over many hours, measure progress even when agents do not explicitly submit, and run reliably on both local machines and clusters. We built SForge around three mechanisms: isolated work and judge environments, a feedback loop modeled on online judges, and progress tracking on the host.
标准的单元测试 harness 不足以支撑天级运行：基准必须隐藏评测资产、支持多小时的重复提交、在智能体不显式提交时也能度量进展，并在本地机器与集群上都能可靠运行。我们围绕三个机制构建了 SForge：相互隔离的工作与评审环境、以在线评测系统为原型的反馈回路，以及主机侧的进展跟踪。
Two-container architecture. Each task is materialized as two task-specific Docker images:
双容器架构。每项任务被实例化为两个任务专属的 Docker 镜像：
• The work image contains the skeleton codebase, documentation, and local validation tools, but no hidden evaluation assets. The agent operates only in this environment.
• 工作镜像包含骨架代码库、文档与本地验证工具，但不含任何隐藏评测资产；智能体只在该环境中运行。
• The judge image contains the hidden evaluation assets, grading scripts, and evaluation commands. It is never exposed to the agent.
• 评审镜像包含隐藏评测资产、评分脚本与评测命令，且从不对智能体暴露。
At evaluation time, the agent’s code is copied into an ephemeral judge container, which runs the hidden tests, returns only task-defined structured feedback, and is then destroyed. This separation prevents agents from inspecting or modifying the hidden grader while still allowing realistic iterative development.
评测时，智能体的代码会被复制进一个临时评审容器：该容器运行隐藏测试、只返回任务定义的结构化反馈，随后即被销毁。这种隔离既防止智能体窥探或篡改隐藏评分器，又不妨碍贴近现实的迭代开发。
Judge server and the outer loop. The outer loop is mediated by a host-side HTTP judge server. The agent submits its current solution to the server, which queues the submission, runs the judge container, parses the result, and returns feedback such as pass rate, score, per-test verdicts, or diagnostics. For long- running evaluations, the server supports asynchronous grading, allowing agents to continue working while submitted jobs are being judged. The server also enforces submission budgets, cooldown intervals, and session authentication.
评审服务器与外回路。外回路由一个主机侧的 HTTP 评审服务器居中协调：智能体将当前解提交给服务器，服务器把提交排入队列、运行评审容器、解析结果，并返回通过率、分数、逐测试判定或诊断信息等反馈。对耗时较长的评测，服务器支持异步评分，智能体可在提交的作业等待评审期间继续工作。服务器还强制执行提交预算、冷却间隔与会话认证。
Long-horizon execution and measurement. SForge combines host-side auto-eval with stop-hook and auto- resume mechanisms to support day-scale runs. Auto-eval periodically snapshots and evaluates the agent workspace through a privileged channel; these results are recorded for trajectory analysis but are not shown to the agent. The stop hook and auto-resume mechanism reduce premature truncation from voluntary exits, crashes, context limits, or transient API failures.
长时程执行与测量。SForge 将主机侧自动评测与 stop hook、自动恢复机制相结合，以支持天级运行。自动评测定期通过特权通道对智能体工作区做快照并评分；这些结果仅记录用于轨迹分析，不向智能体展示。stop hook 与自动恢复机制则减少了因主动退出、崩溃、上下文超限或瞬时 API 故障造成的过早截断。
Operational support and safeguards. SForge also provides practical infrastructure for running and audit- ing large-scale experiments. A web dashboard records score trajectories, submission histories, diffs, and conversation traces for live monitoring and post-hoc comparison. The same task specification can run on either a local Docker backend or a Kubernetes backend for cluster-scale evaluation. To preserve benchmark integrity, SForge combines work–judge isolation with submission filtering, network isolation, and session-scoped authentication, so agents can receive feedback without access to hidden tests, privileged history, or auto-eval results. Appendix C describes task-design failure modes we observed during benchmark development and the corresponding mitigations.
运行支持与安全保障。SForge 还为运行与审计大规模实验提供了实用基础设施：网页仪表盘记录分数轨迹、提交历史、diff 与对话踪迹，供实时监控与事后比较；同一任务规约既可在本地 Docker 后端运行，也可在 Kubernetes 后端上做集群级评测。为维护基准完整性，SForge 将工作-评审隔离与提交过滤、网络隔离及会话级认证相结合，使智能体在不接触隐藏测试、特权历史或自动评测结果的前提下获得反馈。附录 C 描述了我们在基准开发期间观察到的任务设计失败模式及相应缓解措施。

B Serving and API StabilityB 服务与 API 稳定性

Sustaining a single agent for 12 hours or more stresses API serving far more than short evaluations do: a day-long run must keep the model, its context, and its tool calls available without interruption, and any serving-side incident in that window can truncate or degrade the trajectory. Our long-horizon tasks therefore unavoidably fold serving stability into what they measure. We view this as appropriate rather than a confound to be engineered away: an agent deployed to work for hours in the real world is subject to exactly these serving realities, so a benchmark for long-horizon learning should reflect them too.
让单个智能体持续运行 12 小时以上，对 API 服务的压力远超短评测：一次天级运行必须不间断地保持模型、上下文与工具调用可用，期间任何服务端事故都可能截断或劣化轨迹。因此，我们的长时程任务不可避免地把服务稳定性纳入了测量范围。我们认为这是恰当的，而非可用工程手段消除的混淆因素：被部署到真实世界连续工作数小时的智能体本就面对这些服务现实，面向长时程学习的基准也应如实反映。

C Evaluation HackingC 评测破解

Long-horizon evaluation gives agents many opportunities to adapt to evaluator feedback. During task construction and adversarial stress tests, we audited traces for strategies that raised measured scores without exercising the intended capability. These observations are development diagnostics, not official model results: affected tasks were revised or excluded, and the cases below motivated safeguards in the final benchmark.
长时程评测给了智能体大量适应评测反馈的机会。在任务构建与对抗性压力测试期间，我们审计了运行轨迹，排查那些未锻炼目标能力却抬高了测量分数的策略。这些观察属于开发阶段的诊断信息，并非正式模型结果：受影响的任务已被修订或剔除，下列案例也促成了最终基准中的各项防护措施。
Feedback as an oracle for hidden answers. In cylinder_wake_prediction, an agent treated per-case absolute errors as equations and reconstructed the hidden targets through more than 400 submissions. A lookup table then scored 1.000 without solving the underlying fluid dynamics problem, whereas the best observed submission based on a physics model scored 0.165.
把反馈当作隐藏答案的谕示。在 cylinder_wake_prediction 中，一个智能体将逐案例的绝对误差当作方程，通过 400 余次提交逐步重建出隐藏目标；随后，一个查找表在未解决底层流体力学问题的情况下拿到了 1.000 分，而基于物理模型的最佳提交仅得 0.165 分。
Optimizing stochastic upper tails. In nethack_dungeon_agent, an agent removed a fixed random seed after recognizing that higher variance increased the chance of a favorable evaluation. Across 311 submissions, its best score was 1,501 while its mean was 484, showing how best-of-N selection can reward repeated sampling as well as policy quality.
优化随机上尾。在 nethack_dungeon_agent 中，一个智能体意识到更高的方差会提高出现有利评测的概率，于是移除了固定的随机种子。在 311 次提交中，其最好分数达 1,501，均值却只有 484——可见 best-of-N 选择奖励的不只是策略质量，还有重复采样本身。
Overfitting evaluator seeds. In bipedalwalker_locomotion_rl, the development judge initially used a single deterministic episode, allowing agents to infer and optimize for the reused seed rather than expected return. D.3 Many-task Aggregation Reveals the Smooth Log-Sigmoid Law
D.3 多任务聚合显现平滑的 log-sigmoid 定律
We now return to the quantity fit in the benchmark: the average over many independently evaluated tasks. As we have observed empirically, the per-task curves are heterogeneous and often visibly jagged, while the cross-task averages are much smoother and become better fit by the log-sigmoid as more tasks are included. In our language, each task is its own finite frontier expansion process on a task-specific task graph. The aggregate theorem therefore answers the central question:
现在回到基准中实际拟合的量：对许多独立评测任务取平均。正如经验观察所示，单任务曲线异质且常常明显锯齿，而跨任务平均则平滑得多，且纳入的任务越多，log-sigmoid 拟合越好。用本文的语言说，每个任务都是其专属任务图上的一个有限前沿扩张过程。于是，聚合定理回答了核心问题：
How can many jagged task curves produce a clean log-sigmoid scaling law after task averaging?
众多锯齿的任务曲线，如何在任务平均后涌现出一条干净的 log-sigmoid 缩放定律？
The answer has two layers. First, because different task environments do not interact with each other, each task can have its own approximate logistic frontier. Second, the benchmark average removes finite-task roughness and becomes a single log-sigmoid when the task midpoints and task speeds are sufficiently concentrated in the many-task limit.
答案分两层。其一，不同任务环境彼此不发生交互，因此每个任务可以拥有自己的近似 logistic 前沿。其二，基准平均消除了有限任务的粗糙性；当任务中点与任务速度在多任务极限下足够集中时，聚合曲线便成为一条单一的 log-sigmoid。
Moving from a single task to a full benchmark introduces three additional sources of variation.
从单个任务扩展到完整基准，会引入三个额外的变异来源。
• Task-level logistic frontier dynamics. Each task has its own task graph, score atoms, influence matrix, cut error, and finite-jump noise. These quantities determine how closely that task’s frontier expansion follows its own logistic limit.
• 任务级 logistic 前沿动态。每个任务都有自己的任务图、分数原子、影响矩阵、割误差与有限跳变噪声；这些量决定了该任务的前沿扩张在多大程度上贴近其自身的 logistic 极限。
• Time-axis alignment. Each task may have its own model-dependent midpoint tmid,b. A benchmark-level fit, however, has only one common midpoint tmid. Therefore the task-specific midpoint shifts must concentrate across tasks.
• 时间轴对齐。每个任务可能有各自的模型相关中点 tmid,b，而基准级拟合只有一个共同中点 tmid，因此各任务的中点偏移必须在任务间充分集中。
• Learning-speed homogeneity. Each task may also have its own frontier speed βb. A benchmark-level fit uses one common speed β, so the model-dependent task learning speeds must concentrate around a shared value.
• 学习速度同质性。每个任务也可能有各自的前沿速度 βb，而基准级拟合只使用一个共同速度 β，因此各任务的模型相关学习速度必须集中到一个共同值附近。
The aggregate theorem says that the log-sigmoid law appears as a population-level limit: finite-task roughness is washed out by averaging, and the remaining task-level logistic frontiers combine into a single curve when their midpoints and speeds are sufficiently aligned.
聚合定理表明，log-sigmoid 定律是一个总体层面的极限：有限任务的粗糙性被平均抹平；当各任务的中点与速度充分对齐时，剩下的任务级 logistic 前沿便合并为一条单一曲线。

D.5 Discussion and LimitationsD.5 讨论与局限
The derivation above gives a sufficient mechanism for the empirical log-sigmoid law. Its assumptions are useful precisely because they identify concrete ways in which the log-sigmoid limit can fail. We therefore treat it as a mechanistic account of the observed regime rather than a claim that all environment-learning curves must be logistic.
上述推导给出了经验 log-sigmoid 定律的一个充分机制。其假设之所以有价值，恰在于它们指明了 log-sigmoid 极限可能失效的具体途径。因此，我们将其视为对所观察区间的机理解释，而非断言所有环境学习曲线都必须服从 logistic 形式。
Finite score granularity. The single-task theory allows finite tasks to remain visibly jagged. Real tasks may contain a few large hidden tests, decisive proof obligations, or high-weight rubric cells. When such score units remain macroscopic, the martingale error term need not vanish for that task, and the realized best-so-far curve can exhibit long plateaus followed by sudden jumps. The aggregate theorem only requires that such coarse units do not dominate the benchmark average. If a non-negligible fraction of benchmark score measure is carried by coarse tasks, the aggregate curve may retain visible jumps or large run-to-run variance even when the average drift is approximately logistic.
有限的分数粒度。单任务理论允许有限任务保持明显锯齿：真实任务可能包含少数大型隐藏测试、决定性的证明义务或高权重的评分单元格。当这些分数单元保持宏观规模时，该任务的鞅误差项未必消失，已实现的迄今最优曲线可能出现「长平台期后突然跳变」的形态。聚合定理只要求这类粗粒度单元不主导基准平均；一旦不可忽视比例的基准分数测度由粗粒度任务承载，即使平均漂移近似 logistic，聚合曲线仍可能保留可见跳变或较大的运行间方差。
Weighted cut mixing. Weighted cut mixing is the core condition of the scaling law. It says that every macroscopic unlocked–locked frontier cut sees approximately product-measure influence. If the task graph has persistent bottlenecks, modules, prerequisite chains, or separated high-transfer and low-transfer regions, then the frontier remembers where it is in the graph, not only how much score measure has been unlocked. In that case, the natural limit is no longer a one-dimensional logistic equation. One should instead expect multi-type dynamics, delayed takeoff, multiple inflection regions, long plateaus, or a sum of sigmoids corresponding to different task modules.
加权割混合。加权割混合是缩放定律的核心条件：它要求每个宏观的解锁-锁定前沿割都近似看到乘积测度式的影响。若任务图存在持续瓶颈、模块化结构、前置依赖链，或高迁移与低迁移区域彼此分离，那么前沿会「记得」自己在图中的位置，而不只是已解锁多少分数测度。此时自然极限不再是一维 logistic 方程，而应预期多类型动态、延迟起飞、多个拐点区域、长平台期，或对应不同任务模块的 sigmoid 叠加。
Attainable support and the fitted ceiling. The analysis treats Smax as the stable score measure of an effective reachable support. This is appropriate when the set of practically attainable score units is fixed over the fitted time window. However, if longer interaction changes what is effectively reachable—for example, if weak transfer routes become usable only at much longer horizons—then the denominator of the normalized score is itself moving. A short-window fit may still provide a useful effective ceiling, but that ceiling should not be interpreted as an indefinite upper bound.
可达支撑与拟合上限。上述分析把 Smax 视为有效可达支撑的稳定分数测度；当实际可达的分数单元集合在拟合窗口内保持固定时，这一处理是恰当的。然而，若更长的交互改变了实际可达的内容——例如弱迁移路径只有在远长的时程下才可用——归一化分数的分母本身就在移动。短窗口拟合仍能给出有用的有效上限，但不应把该上限解读为无期限的上界。
Task midpoint alignment. The aggregate theorem assumes that a single benchmark-level midpoint removes most task-level log-time bias. If residual midpoint shifts δb remain widely dispersed, the benchmark average becomes a convolution of shifted task frontiers. Such a curve may still be smooth and S-shaped, but it need not satisfy the scalar logistic ODE. In this regime, the fitted midpoint and slope are window-dependent summaries of the task-midpoint distribution rather than intrinsic benchmark constants.

Learning-speed concentration. The aggregate theorem also assumes that task frontier speeds concentrate around a common value. If some task families have persistently steep frontiers while others have persistently shallow frontiers, then the average of task-level sigmoids is generally not itself a sigmoid. Early progress may be dominated by fast tasks, while later progress may be governed by slower tasks. A single fitted β may therefore reflect task-family composition rather than a true scalar environment-learning speed.
学习速度集中。聚合定理还假设各任务前沿速度集中于一个共同值附近。若部分任务族的前沿持续陡峭、另一部分持续平缓，任务级 sigmoid 的平均一般就不再是 sigmoid：早期进展可能由快任务主导，后期进展则由慢任务支配。因此，单一拟合的 β 可能反映的是任务族构成，而非真实的标量环境学习速度。

F.1 Benchmarks Not Suitable for Measuring Self-Evolution
F.1 不适合度量自我进化的基准
Many benchmarks evaluate whether models or agents can answer questions, complete tasks, or produce correct artifacts, without making self-evolution itself the object of measurement. We use this label in a narrow evaluation sense: these benchmarks may still involve reasoning, tools, iteration, or environment interaction, but their primary reported quantity is not related to learning. It is usually final-answer accuracy, task success, pass rate, artifact quality, reproduction fidelity, or human-time horizon. In such settings, interaction is typically a means to produce a final answer or artifact, rather than the quantity being measured.
许多基准评估模型或智能体能否回答问题、完成任务或产出正确产物，却并不把自我进化本身作为度量对象。我们在狭义的评测意义上使用这一标签：这些基准或许同样涉及推理、工具、迭代或环境交互，但其核心报告指标与学习无关——通常是最终答案准确率、任务成功率、通过率、产物质量、复现保真度或人类时间时程。在这类设定中，交互通常只是产出最终答案或产物的手段，而非被度量的对象。
At the shortest and least interactive end, many classic capability benchmarks, such as MMLU [28], GPQA [59], AIME [43], and closed-form coding or math evaluations [11, 29], ask models to solve static problems and report final accuracy. These benchmarks can be difficult and useful, but the model’s actions do not create a changing environment, and feedback from the benchmark is not exposed as experience for later adaptation. They therefore measure static knowledge and reasoning accuracy rather than self-evolution.
在时程最短、交互最弱的一端，许多经典能力基准——如 MMLU [28]、GPQA [59]、AIME [43] 以及封闭式编程或数学评测 [11, 29]——要求模型解决静态问题并报告最终准确率。这些基准可以很难、也很有用，但模型的行动不会创造一个持续变化的环境，基准反馈也不作为经验暴露给模型供后续适应。因此，它们度量的是静态知识与推理准确率，而非自我进化。
Agentic software benchmarks increase realism by placing agents in codebases, development workflows, or larger construction tasks, but many still reduce evaluation to the final result. SWE-bench [34] evaluates issue repair in existing repositories; development and evolution benchmarks such as RoadmapBench [75] and SWE- EVO [67] evaluate incremental changes over existing projects or release histories; construction or reconstruction benchmarks such as NL2Repo-Bench [18] and ProgramBench [77] evaluate complete repository generation or recovery of program behavior; and SWE-AGI [81] evaluates specification-driven system construction under a fixed MoonBit API scaffold. FrontierCode [39] raises the bar on readiness for production by evaluating whether coding agents produce maintainable, mergeable changes under repository-specific quality rubrics. Their task formats differ, but the shared evaluation target is final patch correctness, repository quality, program behavior, maintainability, or test pass rate rather than the trajectory by which an agent improves from feedback.
智能体软件基准通过把智能体置于代码库、开发工作流或更大的构建任务中来提升现实感，但许多仍将评测简化为最终结果。SWE-bench [34] 评估现有仓库中的 issue 修复；RoadmapBench [75] 与 SWE- EVO [67] 等开发与演化基准评估对现有项目或发布历史的增量变更；NL2Repo-Bench [18] 与 ProgramBench [77] 等构建或重建基准评估完整仓库生成或程序行为恢复；SWE-AGI [81] 在固定的 MoonBit API 脚手架下评估规约驱动的系统构建。FrontierCode [39] 则以仓库特定的质量细则检验编码智能体能否产出可维护、可合并的变更，提高了「生产就绪」的门槛。这些基准的任务格式各异，但共同的评测目标都是最终补丁正确性、仓库质量、程序行为、可维护性或测试通过率，而非智能体从反馈中改进的轨迹。
Some evaluations broaden realism without becoming agentic learning benchmarks. GDPval [57], for example, measures model performance on economically valuable professional deliverables across occupations. Agents’ Last Exam [66] is a close comparator in realism and autonomy: it evaluates generalist computer-use agents on economically valuable professional workflows in real Windows or Linux sandboxes, with CLI and GUI access, professional software, hidden references, and verifiable final artifacts. The distinction is the evaluation target rather than agenticity. Agents’ Last Exam is oriented toward completion: agents work toward a final deliverable, and the benchmark reports final scores, pass rates, cost, or time after the artifact is graded. Its trajectories are valuable for replay, audit, and failure analysis, but learning from the benchmark’s feedback over a run is not the main quantity being measured.
还有一些评测在不成为智能体学习基准的前提下提升了现实感。例如 GDPval [57] 度量模型在各职业中有经济价值的专业交付物上的表现。Agents' Last Exam [66] 在现实性与自主性上与本文最为接近：它在真实的 Windows 或 Linux 沙箱中评测通用计算机操作智能体完成有价值的专业工作流，具备 CLI 与 GUI 访问、专业软件、隐藏参考资料与可验证的最终产物。二者的区别在评测目标，而非「智能体化」程度。Agents' Last Exam 以完成为导向：智能体朝最终交付物推进，基准在产物评分后报告最终分数、通过率、成本或耗时。其轨迹对回放、审计与失败分析颇有价值，但「一次运行中从基准反馈中学习」并非其度量的核心量。
Other benchmarks use realistic or long-horizon workflows that could support learning, but their published protocols mainly measure final outcomes. HCAST [60] and METR time-horizon evaluations [37] calibrate model or agent success by human task duration. Terminal-Bench [44], RE-Bench [71], PaperBench [65], CORE-Bench [63], PRBench [58], ReplicationBench [78], Collider-Bench [23], and ScienceAgentBench [12] involve executable software tasks, terminal workflows, or scientific reproduction. These settings are more compatible with learning than short closed-form tasks, but their central questions are typically whether a task is completed, an artifact works, a paper is reproduced, or a final score is high enough under a budget. PaperBench is a useful example of the distinction: it evaluates agentic replication of 20 ICML papers from scratch using detailed rubrics and many gradable subtasks, but the reported score is still replication quality rather than improvement per unit of feedback.
另一些基准采用现实的或长时程的工作流，本可支持学习，但其公开协议主要度量最终结果。HCAST [60] 与 METR 时间时程评测 [37] 以人类任务时长校准模型或智能体的成功。Terminal-Bench [44]、RE-Bench [71]、PaperBench [65]、CORE-Bench [63]、PRBench [58]、ReplicationBench [78]、Collider-Bench [23] 与 ScienceAgentBench [12] 则涉及可执行软件任务、终端工作流或科学复现。这些设定比短小的封闭式任务更兼容学习，但其核心问题通常是：任务是否完成、产物是否可用、论文是否被复现，或预算内最终分数是否够高。PaperBench 是说明这一区别的好例子：它以详细细则与大量可评分子任务评估智能体从零复现 20 篇 ICML 论文的能力，但报告的分数仍是复现质量，而非单位反馈带来的改进。

Context-learning benchmarks study the least agentic form of adaptation. CL-bench [21] and CL-bench Life [20] test whether models can use newly provided professional or personal context to answer downstream questions or perform tasks grounded in that context. Sequential learning benchmarks introduce a stream-like structure. EvaLearn [19] groups 648 problems into 182 sequences and evaluates learning capability and efficiency as models solve related problems in order. Continual Learning Bench [4] explicitly reports improvement over sequential experience and introduces a stateful-versus-stateless comparison similar to Section 5.2. However, its synthetic task sequences have explicit subtask boundaries, whereas EdgeBench uses single continuous problems. We therefore partition by time rather than by subtask, which changes how the stateful and stateless settings are defined. StreamBench [73] also reports improvement over feedback streams. LLF-Bench [13], LifelongAgentBench [82], and Evo-Memory [69] study related questions through language feedback, interdependent tasks, experience replay, or evolving memory. These works establish that static capability and learning ability are distinct axes. The difference from EdgeBench is not that their interaction is necessarily weaker; rather, the sequence is usually organized by the benchmark as a series of instances, tasks, feedback events, or memory updates. In EdgeBench, the sequence is endogenous to one long task: the agent plans, edits artifacts, submits attempts, receives diagnostics, and thereby affects what it learns next.
序列学习基准引入了流式结构。EvaLearn [19] 将 648 个问题组成 182 个序列，在模型按序解决相关问题的过程中评估学习能力与效率。Continual Learning Bench [4] 显式报告对序列经验的改进，并引入与 5.2 节类似的有状态 vs 无状态比较；但其合成任务序列带有显式子任务边界，而 EdgeBench 使用单一连续问题，因此我们按时间而非按子任务划分，这也改变了有状态与无状态设定的定义方式。StreamBench [73] 同样报告对反馈流的改进。LLF-Bench [13]、LifelongAgentBench [82] 与 Evo-Memory [69] 则通过语言反馈、相互依赖任务、经验回放或演化记忆研究相关问题。这些工作确立了静态能力与学习能力是两个不同的轴。它们与 EdgeBench 的区别不在于交互必然更弱，而在于其序列通常由基准组织为一系列实例、任务、反馈事件或记忆更新；而在 EdgeBench 中，序列内生于单一长任务——智能体规划、编辑产物、提交尝试、接收诊断，从而塑造它接下来学到的东西。
Iterative optimization benchmarks are closer to EdgeBench because they make repeated attempts and empirical feedback central to performance. Frontier-Eng [14] studies improvement over generative optimization cycles, while MLS-Bench [40] and Frontier-CS [41] evaluate test-time discovery or open-ended CS optimization with visible metrics, submissions, or trajectory-level reporting. MLE-bench [10] is also naturally viewed in this family: agents work in a free Kaggle-style workspace, the paper includes studies of how performance scales with resources, and its 100-hour analysis grades snapshots of the agent’s best attempt over elapsed time. ALE-Bench [33] is another adjacent long-horizon setting driven by fixed objectives, even though its original protocol primarily reports outcomes on algorithm engineering rather than learning metrics.
迭代优化基准与 EdgeBench 更接近，因为它们把重复尝试与经验反馈置于性能度量的核心。Frontier-Eng [14] 研究生成式优化循环中的改进；MLS-Bench [40] 与 Frontier-CS [41] 以可见指标、提交记录或轨迹级报告评估测试时发现或开放式 CS 优化。MLE-bench [10] 也可自然归入这一族：智能体在自由的 Kaggle 风格工作区中工作，该工作包含性能随资源扩展的研究，其 100 小时分析按经过时间对智能体最佳尝试的快照评分。ALE-Bench [33] 是另一个由固定目标驱动的相邻长时程设定，尽管其原始协议主要报告算法工程的结果而非学习指标。
FrontierSWE [15] and AutoLab [76] are the closest prior work. Both evaluate long-horizon agentic improvement over executable artifacts through repeated edits, experiments, and empirical feedback. FrontierSWE focuses on software engineering and performance-tuning tasks, with reported average agent runtime of roughly 3–4 hours across models and task categories. AutoLab gives agents working but deliberately suboptimal programs across systems, CUDA, model development, and puzzle-style optimization tasks; it directly measures iterative improvement and should not be treated as a non-learning benchmark, although performance curves are not reported as the main result and most current tasks run for 2–4 hours, with only a small minority exceeding 6 hours. Under the shared premise of long-horizon agentic tasks, the main distinction is domain coverage: FrontierSWE is concentrated on software engineering, AutoLab emphasizes research and engineering tasks centered on optimization, and EdgeBench spans a broader set of executable domains. EdgeBench also uses a day-scale task contract and makes the time-aligned trajectory itself the primary object of measurement, with metrics for improvement area, regression, and active learning span.
FrontierSWE [15] 与 AutoLab [76] 是与本文最接近的先行工作：两者都通过重复编辑、实验与经验反馈评估对可执行产物的长时程智能体改进。FrontierSWE 聚焦软件工程与性能调优任务，报告的平均智能体运行时间（跨模型与任务类别）约为 3–4 小时。AutoLab 给智能体可用但刻意次优的程序，覆盖系统、CUDA、模型开发与谜题式优化任务；它直接度量迭代改进，不应被当作非学习基准——尽管性能曲线并非其主要报告结果，且当前大多数任务运行 2–4 小时，仅少数超过 6 小时。在「长时程智能体任务」的共同前提下，主要区别在于领域覆盖：FrontierSWE 集中于软件工程，AutoLab 侧重以优化为核心的研究与工程任务，而 EdgeBench 横跨更广的可执行领域。此外，EdgeBench 采用天尺度任务契约，并把时间对齐的轨迹本身作为首要度量对象，配有改进面积、回退与主动学习跨度等指标。
Taken together, these benchmarks cover important pieces of the problem: realistic executable work, learning over organized streams, and iterative optimization under feedback. EdgeBench targets their intersection. It evaluates within-run self-evolution in long-horizon executable environments where the experience stream arises from the task itself, the agent can influence what it observes next, and evaluation uses a general-purpose agent harness rather than a benchmark-specific learning scaffold. Its trajectory-level metrics report improvement, regression, active learning span, and final performance over the same continuous run.
综合来看，这些基准各自覆盖了问题的重要侧面：现实的可执行工作、有组织数据流上的学习，以及反馈下的迭代优化。EdgeBench 瞄准的正是它们的交集：在长时程可执行环境中评估运行内自我进化——经验流源于任务本身，智能体能影响自己接下来观察到什么，评测则使用通用智能体 harness 而非基准专属的学习脚手架。其轨迹级指标在同一次连续运行上报告改进、回退、主动学习跨度与最终性能。
F.3 Scaling Laws for LLMs and Agents
F.3 LLM 与智能体的缩放定律
Classical neural and language-model scaling laws mainly study pretraining, modeling reducible loss as a function of model size, data, and training compute. Kaplan et al. [35] showed that language-modeling loss follows power-law relationships over several axes of scale, and Chinchilla-style work refined the compute-optimal allocation between model parameters and training tokens [31]. More recent work studies how benchmark performance, rather than loss, changes with scale; because accuracy-like metrics are bounded, these curves are often better described by sigmoidal or other saturating forms [7, 56, 61, 80]. Our log-sigmoid environment learning curves in Section 3 are closest in mathematical form to this bounded-performance line of work, but the independent variable is elapsed environment interaction within a task rather than pretraining compute or model scale.
经典的神经网络与语言模型缩放定律主要研究预训练，把可约简损失建模为模型规模、数据与训练算力的函数。Kaplan et al. [35] 表明语言建模损失在多个规模轴上服从幂律关系；Chinchilla 式工作则细化了模型参数与训练 token 之间的算力最优分配 [31]。较新的工作转而研究基准性能（而非损失）如何随规模变化；由于类准确率指标有界，这类曲线往往更适合用 sigmoid 或其他饱和形式描述 [7, 56, 61, 80]。我们在第 3 节得到的 log-sigmoid 环境学习曲线在数学形式上与这一「有界性能」研究线最为接近，但自变量是任务内经过的环境交互时长，而非预训练算力或模型规模。
Test-time and inference-time scaling provide a second point of comparison: different test-time methods exhibit their own empirical scaling behavior. One line scales plain repeated sampling: Evaluating Large Language Models Trained on Code introduced pass@k as a repeated-sampling evaluation for code generation [11], AlphaCode used large-scale sampling, filtering, and selection to improve competitive-programming solve rates [38], and Large Language Monkeys showed that repeated sampling can scale coverage across orders of magnitude when outputs are automatically verifiable [9]. A second line studies how test-time compute should be allocated across search, revision, voting, and verifier- or reward-guided strategies [64, 74]. A third line scales long-chain-of-thought inference in reasoning models: OpenAI’s o1 report made train-time reinforcement learning compute and test-time thinking compute explicit scaling axes [47], and DeepSeek-R1 studies how reinforcement learning can elicit reasoning behaviors in LLMs [16]. These studies mostly scale the compute spent producing or selecting answers on traditional math, code, proof, or game-style tasks, and the reported functional forms are often local log-linear trends, exponentiated power laws, or frontiers for allocating compute. EdgeBench instead scales interaction time: it measures how an agent’s best-so-far performance changes as elapsed time in an executable environment increases and as the agent repeatedly reads, acts, receives feedback, and revises. This gives broader task coverage and a different scaling object than sampling from a static prompt or selecting among answers.
测试时与推理时缩放提供了第二个比较维度：不同测试时方法各有其经验缩放行为。第一条线扩展朴素重复采样：Evaluating Large Language Models Trained on Code 引入 pass@k 作为代码生成的重复采样评测 [11]；AlphaCode 借助大规模采样、过滤与选择提高竞赛编程解题率 [38]；Large Language Monkeys 表明，当输出可自动验证时，重复采样能把覆盖率提升数个数量级 [9]。第二条线研究测试时算力应如何在搜索、修订、投票以及验证器或奖励引导的策略之间分配 [64, 74]。第三条线扩展推理模型中的长思维链推理：OpenAI 的 o1 报告把训练时强化学习算力与测试时思考算力确立为显式的缩放轴 [47]；DeepSeek-R1 研究强化学习如何在 LLM 中诱发推理行为 [16]。这些研究大多扩展的是在传统数学、代码、证明或博弈型任务上生成或筛选答案所花费的算力，其报告的函数形式通常是局部 log-linear 趋势、指数化幂律或算力分配前沿。EdgeBench 则缩放交互时间：度量智能体的迄今最优性能如何随可执行环境中经过时间的增加而变化——智能体在其中反复读取、行动、接收反馈并修改。相比从静态 prompt 采样或在候选答案间选择，这带来了更广的任务覆盖与一个不同的缩放对象。
Recent agentic test-time scaling work moves closer to our setting by allowing agents to acquire information from an environment over time. OpenAI’s CUA report observed that computer-use performance improves when more steps are allowed [49], and BrowseComp reports smoother gains as browsing effort increases [68]. Thinking vs. Doing explicitly frames interaction length as a test-time scaling axis for web agents [62]. Closest in spirit, Mang et al. [42] compare agents and humans on a long-horizon coding contest setting where agents can try, observe, and revise over time. They report an informative human reference curve and find that current agents plateau while strong humans continue improving. However, the measurement is concentrated in one contest-style domain and a limited task set. The human improvement curve is also difficult to extrapolate: the observed segment appears closer to linear improvement over time, but it may cover only the early portion of a longer sigmoid-like trajectory.
近期的智能体测试时缩放工作与我们的设定更为接近：允许智能体随时间从环境中获取信息。OpenAI 的 CUA 报告观察到，允许更多步数时计算机操作性能会提升 [49]；BrowseComp 报告随浏览投入增加收益更平滑 [68]；Thinking vs. Doing 则显式地把交互长度框定为 web 智能体的测试时缩放轴 [62]。精神上最接近的是 Mang et al. [42]：他们在长时程编程竞赛设定中比较智能体与人类，允许智能体随时间尝试、观察与修改；他们报告了一条颇具参考价值的人类改进曲线，并发现当前智能体进入平台期，而强人类仍在持续改进。不过，其测量集中于单一竞赛型领域与有限任务集；人类改进曲线也难以外推——观测段看起来更接近随时间的线性改进，但也可能只是更长 sigmoid 型轨迹的早期部分。
Scaling has also been studied in reinforcement learning. Hilton et al. [30] introduced intrinsic performance to obtain smooth power-law relations between environment interactions, model size, and RL performance. Recent LLM RL scaling work fits sigmoidal compute-performance curves for post-training and uses smaller runs to predict larger RL runs [36]. Both RL and our evaluation measure learning from environment feedback rather than from human-labeled data. The practical difference is resolution and coverage. RL learning runs are expensive, so scaling evidence is usually gathered on narrower task distributions, fewer distinct environments, and fewer long trajectories. In EdgeBench, the learning algorithm is in-context learning (ICL): the agent absorbs observations, diagnostics, and prior attempts into its context and uses them to improve subsequent actions. Because ICL is cheaper to repeat than RL training, EdgeBench can measure environment learning across 134 executable task environments, multiple domains, full time-aligned trajectories, and repeated trials, yielding substantially broader environment coverage than is typical in RL scaling studies. The resulting fits go beyond a bounded-performance analogy to RL scaling: they provide a higher-resolution measurement of how agents learn from interaction.
强化学习中也研究过缩放。Hilton et al. [30] 引入内在性能，得到了环境交互、模型规模与 RL 性能之间的平滑幂律关系；近期的 LLM RL 缩放工作为后训练拟合 sigmoid 形的算力-性能曲线，并用较小规模的运行预测更大的 RL 运行 [36]。RL 与本文评测都度量从环境反馈中的学习，而非从人类标注数据中学习；实际差别在分辨率与覆盖面：RL 训练运行昂贵，缩放证据通常只能在更窄的任务分布、更少的不同环境与更少的长轨迹上收集。在 EdgeBench 中，学习算法是上下文学习（ICL）：智能体把观测、诊断与先前尝试吸收进上下文，并据此改进后续动作。由于 ICL 的重复成本远低于 RL 训练，EdgeBench 能在 134 个可执行任务环境、多个领域、完整的时间对齐轨迹与重复试验上度量环境学习，其环境覆盖远超 RL 缩放研究的典型水平。由此得到的拟合也超越了对 RL 缩放的有界性能类比：它以更高分辨率度量了智能体如何从交互中学习。

G.3 Harness-Level Continuation AblationsG.3 Harness 级续跑消融
Long-running agent evaluation depends not only on model capability, but also on how the harness keeps the run alive and carries useful state across many hours. In a 12-hour task, an agent may stop its running unexpectedly due to idleness and need to resume. These continuation mechanisms are therefore part of the practical measurement setup: a weak scaffold can make a capable model stop working on the task, while a stronger scaffold may help the same model keep active and improving. As a supplementary harness-level ablation, we evaluate two such mechanisms, /goal mode and the Ralph loop, under a fixed 12-hour budget with GPT-5.5 and GPT-5.4.
长时运行的智能体评测不仅取决于模型能力，也取决于 harness 如何在数小时内维持运行并携带有效状态。在 12 小时任务中，智能体可能因空闲而意外中止运行、需要恢复。因此，这些续跑机制本身就是实际测量设置的一部分：弱脚手架可能让有能力的模型停止工作，而更强的脚手架则可能帮助同一模型保持活跃、持续改进。作为补充性的 harness 级消融，我们在固定 12 小时预算下，用 GPT-5.5 与 GPT-5.4 评估了两种此类机制：/goal 模式与 Ralph loop。
Base uses the standard harness: one continuing agent session, a stop hook to prevent voluntary early exit, and auto-resume for abnormal exits. In /goal mode [53], the harness prompts the agent to create a task-level goal at the beginning, keep it active during the run, and mark it complete only when the task is validated. The Ralph loop follows the file-backed fresh-context pattern [32]: each loop starts a new agent invocation on the same workspace, asks it to read and update progress.md, then appends judge feedback to that file before the next loop. It uses up to 100 loops, a 7200-second per-loop cap, and the same 12-hour overall budget. Each cell schedules three runs and reports the mean score over valid runs.
Base 使用标准 harness：单一持续智能体会话、防止主动提前退出的 stop hook，以及针对异常退出的自动恢复。在 /goal 模式 [53] 下，harness 提示智能体在任务开始时创建任务级目标，运行期间保持其活跃，且只有任务通过验证后才标记完成。Ralph loop 遵循文件支撑的新鲜上下文模式 [32]：每轮循环在同一工作区上启动一次新的智能体调用，要求其读取并更新 progress.md，并在下一轮循环前把评审反馈追加进该文件。它最多使用 100 轮循环、每轮上限 7200 秒，总预算同为 12 小时。每个单元格安排三次运行，报告有效运行的分数均值。

G.6 Per-Task Score TablesG.6 逐任务分数表
For every task–model configuration, we scheduled three independent long-horizon runs. In practice, because these 12-hour trajectories are sensitive to network instability and serving-side reliability limits, we carried out multiple rolling evaluation rounds to recover failed or incomplete runs and produced the final score tables below. A small number of reported task–model cells nevertheless still have fewer than three valid runs; those cells are marked with *. Each run score is first rescaled to the 0–100 task scale; the adjacent ±s term reports the sample standard deviation across these rescaled run scores when at least two valid runs are available. This standard deviation is not clipped to the 0–100 range, so ¯x ± s should be read as run-to-run variation rather than as a bounded score interval.
对每个任务-模型配置，我们均安排三次独立的长时程运行。实践中，由于 12 小时轨迹对网络不稳定与服务端可靠性限制较为敏感，我们执行了多轮滚动评测以补跑失败或不完整的运行，并产出下方最终分数表。尽管如此，少数报告的任务-模型单元格的有效运行仍不足三次，这些单元格以 * 标记。每次运行分数先缩放到 0–100 任务量表；当有效运行不少于两次时，相邻的 ±s 项报告这些缩放后运行分数的样本标准差。该标准差未截断到 0–100 范围内，因此 ¯x ± s 应理解为运行间波动，而非有界的分数区间。
